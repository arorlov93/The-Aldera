# Growth Analytics — ритм управления машиной

Опоры: docs/BATCH_ECONOMICS (план), track5/tiktok_shopify_economics.md (нормативы CM),
track6/creator_tracker.csv (криейтеры), docs/FINMODEL_V2.md (RP-формула).
Формат: один еженедельный отчёт владельцу (вс/пн), одна страница, факт против плана.

## 1. Панель недели (обязательные блоки)
1. **Продажи**: ед/день по SKU × канал (TikTok/Shopify/Amazon), неделя к неделе.
2. **Деньги**: выручка, CM факт ($/ед против норматива ~$10), живые расходы, кэш
   нарастающим итогом против плана окупаемости (вход ≈ $22-25k, безубыток ~2,500 ед).
3. **Криейтеры**: активных/постов/продаж за неделю, топ-5 леаборд, № золотых,
   конверсия текущей волны против норм воронки (см. creator-outreach §1).
4. **Листинги**: рейтинг (алерт < 4.5), позиции по ключевым запросам, флаги модерации.
5. **Склад и ресток**: остатки по SKU, дней до нуля при текущем темпе,
   **RP = units/day × 66** — алерт «пора депозит рестока» автоматически по формуле.
6. **Решения недели**: максимум 3 пункта, каждый с ценой вопроса в $ (например:
   «магний закончится 4 января — депозит рестока $2.2k до 27 декабря»).

## 2. Алерты между отчётами (не ждём воскресенья)
- Продажи SKU падают 3 дня подряд >30% → разбор в тот же день.
- Рейтинг листинга < 4.5 · заморозка модерацией · любой отзыв 1-2★ → немедленно.
- Остаток героя < RP → в тот же день считать ресток.
- Виральный всплеск (>3x дневной нормы) → проверить остатки и поднять цену flash-окна.

## 3. Правила чтения цифр
- Одна плохая неделя = шум; две = тренд; тренд = меняем (хук/цену/криейтеров), а не ждём.
- CM/ед ниже норматива на >15% → искать утечку (скидки? возвраты? фулфилмент?).
- Сравнение только с планом и прошлой неделей — не с мечтой.

## 4. Источники данных
TikTok Seller Center (экспорт CSV) · Shopify Analytics (UTM/коды) · creator_tracker ·
банковские выписки (владелец скидывает суммы). Всё складываю в track7/weekly/ (создать
при первом отчёте) и веду факт-таблицу track7/actuals.csv: date,sku,channel,units,revenue.
